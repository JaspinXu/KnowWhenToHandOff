# SFT Token Batch Implementation Plan

> Execute inline with test-driven-development and one independent code review.

**Goal:** Convert existing sampled-token rollouts into correctly masked SFT
minibatches using the standard library, without a trainer or new dependencies.

**Spec:** README T2.2 (assistant-only loss), component token contracts, AGENTS
test-split protection. ADR-006 and ADR-007 remain deferred.

## Design and boundaries

`src/handoff/train/sft_batch.py` provides frozen `SFTBatchConfig` with
`max_length`, `pad_token_id`, `ignore_index`, `pad_to_multiple_of`, plus
`sft_config_from_mapping(config)` and `build_sft_batch(samples, *, config)`.
Each sample is a mapping containing exactly `split`, `prompt_ids`, `response_ids`
and `response_mask`; the three token arrays come directly from TokenAccumulator.

Return `input_ids`, `attention_mask`, `labels` as lists of rows in source order.
Use right padding, no packing, no truncation or added special tokens. Labels are
unshifted: ignore prompt/observation/padding positions, copy policy token IDs to
their own positions. The future causal-LM trainer applies its usual one-token
shift once. Real EOS IDs equal to the pad ID still retain labels and attention.

Accept only caller-declared `split="train"`; reject other/missing values before
creating any output. This is an input guard, not authentication of upstream
membership or lineage. Eligibility filtering (successful, compliant, correct
handoff), registry validation, tokenization and actual optimization remain pending.

## Review focus

Loss/attention masking must use positions, not token equality; labels must not be
shifted twice; no dev/test row may survive a mixed batch; invalid inputs must not
be silently dropped or truncated; config values and output arrays must not alias
mutable input buffers. No claims of actual gradient/transformers/GPU validation.
