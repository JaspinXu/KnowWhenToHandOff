# Independent runtime utilities

These modules are CPU-tested prerequisites. They do not implement the benchmark
adapter, evaluator, rewards, SFT trainer, or verl loop. ADR-006 remains deferred.

## Run provenance

`handoff.ops.provenance.create_run_directory(root, run_id=..., config=...,
provenance=...)` creates a new run directory and refuses to overwrite it.
Supply a configured scratch root for real runs. The caller passes observed
metadata; the helper never invents a revision, seed or hardware inventory.

Required provenance fields:

| Field | Contract |
| --- | --- |
| `purpose` | Nonempty description of the run |
| `execution_kind` | `real` or `synthetic_test`, explicitly supplied |
| `git_sha`, `tau2_sha` | Full immutable 40-character commit IDs |
| `git_dirty` | Explicit boolean; must be false for real runs |
| `model_revisions` | Full commit IDs, including `policy` and `user_sim` |
| `seeds` | Named nonnegative integers; `run` must match the run ID's seed |
| `hardware` | Nonempty, deliberately selected observed hardware metadata |

Run IDs follow the README experiment matrix, for example
`R2-fp05-s1-20261024`. The date must be valid. Dates and seeds in examples are
illustrative and are not evidence that an experiment occurred.

The directory contains a sanitized `config.json` and `provenance.json` with its
SHA-256 hash. Its initial state is `initialized`; creating a directory does not
run an experiment. Known credential keys are redacted recursively. Unresolved
Hydra values, nonfinite numbers and credential-bearing HTTP URLs are rejected.
Do not pass the entire environment, raw credentials, arbitrary user text or
personal information: key-based redaction is a secondary safeguard, not a general
secret detector.

`verify_run_directory(path)` verifies the immutable initial provenance and exact
config hash. It returns that initial record, not a current lifecycle status.
`finish_run(path, status=..., error_code=...)` writes `completion.json` once:
status is `completed`, `failed` or `interrupted`. Error codes are bounded
uppercase identifiers, never raw exceptions. A completed execution does not mean
that a performance target or research milestone passed.

The first caller to create a run/completion file wins; subsequent writers fail
instead of overwriting provenance. Initialization failure removes only files
created by that attempt. These files are not signed; hashes detect accidental
config changes, not malicious replacement of both config and provenance.

No tracker is contacted and no experiment-log entry is fabricated. Later live
drivers must call the recorder with actual source/model revisions and append
their real results to the experiment log.

## Sampled-token preservation

`handoff.rollout.tokens.TokenAccumulator` accepts actual token IDs:

```python
from handoff.rollout.tokens import TokenAccumulator

buffer = TokenAccumulator([10, 20], max_response_tokens=16)
buffer.append("assistant", [101, 102])  # IDs returned by policy generation
buffer.append("tool", [201])           # encoded tool observation
buffer.append("user", [301, 302])      # encoded simulated user observation
buffer.append("assistant", [103])
batch = buffer.as_output()
assert batch["response_ids"] == [101, 102, 201, 301, 302, 103]
assert batch["response_mask"] == [1, 1, 0, 0, 0, 1]
```

Tool-call text generated by the policy is still appended as `assistant` and
receives mask 1. The tool's response receives mask 0. The initial prompt stays in
`prompt_ids`, outside the response mask. Multiple consecutive tool observations
are allowed. Empty segments are no-ops.

The accumulator never tokenizes text, reconstructs a transcript or silently
truncates. Capacity covers all response tokens, including observations, and
overflow fails before mutation. Callers must terminate/truncate an episode
explicitly under their eventual approved protocol. Input and output arrays are
copied, so later mutation cannot corrupt stored IDs or masks.

This helper does not supply behavior log probabilities, attention/position IDs,
advantages, rewards or a verl `AgentLoopOutput`. The live trainer adapter must
integrate those and prove eval/train parity before T3.1 is complete.

For supervised training preparation, [SFT batching](sft-batches.md) now consumes
these exact three token arrays with a caller-supplied train split declaration.
It retains policy IDs and masks prompt/observation/padding positions in the loss
labels. It is not a trainer or a verifier of upstream task membership.

## Local verification

```bash
uv run pytest -q tests/test_provenance.py tests/test_tokens.py
```

Every test uses temporary files and explicitly synthetic metadata; none downloads
a model or reports an experimental score.
